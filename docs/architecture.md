# 設計と実装の現状

この文書は `src/main.cpp` と `platformio.ini` から読み取れる現在の実装を説明します。
将来の構想ではなく、動作する部分と未実装部分を区別して記載しています。

## ビルド環境

PlatformIO の環境名は `esp32dev` です。Espressif 32 platform、Arduino framework、
汎用 ESP32 Dev Module を対象とします。シリアルモニターは 115200 bps、アップロードは
1,000,000 bps です。

デバッグレベルは `CORE_DEBUG_LEVEL=4`、ログ色は有効です。依存関係には
`ESP Async WebServer` が宣言されていますが、現在のコードが使用するのは Arduino
ESP32 core の同期型 `WebServer` です。そのため、この依存関係は現状のソースからは
利用されていません。

## 起動シーケンス

`setup()` は次の順に初期化します。

1. シリアル通信を 115200 bps で開始する。
2. ESP32 をアクセスポイントモードにする。
3. SSID `BarGraqh`、パスワード `password` で SoftAP を開始する。
4. 100 ms 待機後、SoftAP を `192.168.0.1/24` に設定する。
5. `esp32` というホスト名で mDNS の開始に成功するまで再試行する。
6. GPIO 27 を出力にし、LEDC channel 0 を接続する。
7. コンパイル時のモードに応じた初期処理を行う。

mDNS の初期化にはタイムアウトがないため、開始できない環境では手順 5 から先へ進みません。

## パルス出力

`pfmWrite(freq)` は LEDC channel 0 を指定周波数、12 bit の分解能で設定し、デューティ値
2048 を書き込みます。12 bit の範囲は 0〜4095 なので、これはほぼ 50% です。

`speedWrite(speed)` は符号付き 16 bit の速度値を受け取り、以下を計算して
`pfmWrite()` へ渡します。

```text
speed * 6.472 + 5.070
```

計算結果は最終的に符号なし 32 bit の周波数へ暗黙変換されます。負の速度、大きすぎる
速度、LEDC が扱えない周波数を拒否または制限する処理はありません。

## モード別フロー

### `SERVER`（現在の既定）

グローバルにポート 80 の `WebServer` を生成します。起動時にサーバーを開始し、mDNS
へ TCP サービスを登録します。`loop()` は `handleClient()` を繰り返します。

ただし、`Server.on(...)` などのハンドラー登録は存在しません。したがって、HTTP で速度や
周波数を設定するエンドポイント、HTML 画面、レスポンス処理はいずれも未実装です。

### `SPEED`

起動時に `speedWrite(100)` を実行します。以降はシリアルから改行までを文字列として読み、
Arduino の `String::toInt()` で整数化して速度として出力します。数値として解釈できない入力は
0 になります。

### `FREQ`

起動時に 1000 Hz を出力します。シリアル入力が 0 の場合は GPIO 27 を LOW にします。
非ゼロの場合は `prmWrite(freq)` を呼んでいますが、その関数は定義されていません。
このモードを有効にするとコンパイルエラーになるため、修正が必要です。

### モード未指定

起動時にモード未設定のログを出します。ループでは受信した文字列をログに表示するだけで、
パルス周波数は設定しません。

複数のモードを同時に定義した場合、プリプロセッサの分岐順により `SERVER`、`SPEED`、
`FREQ` の順で最初のものだけが選ばれます。意図が分かりにくくなるため、定義は必ず 1 つに
してください。

## 固定設定

次の値はすべて `src/main.cpp` に直接記述されています。

| 項目 | 値 |
| --- | --- |
| 出力 GPIO | 27 |
| SoftAP SSID | `BarGraqh` |
| SoftAP パスワード | `password` |
| SoftAP IP / gateway | `192.168.0.1` |
| subnet mask | `255.255.255.0` |
| mDNS hostname | `esp32` |
| HTTP port | 80 |

公開環境で使う場合は認証情報をソース管理から分離し、安全な値に変更してください。

## 既知の制約と改善候補

- `SERVER` モードには HTTP ルートがなく、外部から出力を制御できない。
- `FREQ` モードには未定義の `prmWrite` 呼び出しがある。
- 入力値と計算後の周波数に範囲検証がない。
- mDNS 開始待ちにタイムアウトやエラー時の代替処理がない。
- Wi-Fi 認証情報とネットワーク設定がソースへ固定されている。
- 宣言された Async Web Server 依存関係と実際に使う同期 Web サーバーが一致しない。
- 自動テストがなく、ハードウェア上の波形確認手順も自動化されていない。

機能変更を行う際は、これらを一度に暗黙修正するのではなく、目的ごとに変更と検証を分け、
README と本書も同じ変更単位で更新してください。
