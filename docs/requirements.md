# 統合制御機能の要求仕様

この文書は今後実装する ControlBarGraph の統合制御機能を定義します。Web UI、端末コマンド、
デモ動作、アナログ手動入力、Wi-Fi フォールバック、2 個の LED はすべて **未実装の要求仕様**
です。現在実装済みの挙動は [設計と実装の現状](architecture.md) を参照してください。

## 目的

従来の `SERVER`、`SPEED`、`FREQ` という排他的なコンパイル時モードは廃止します。単一の
ファームウェアで Web UI、シリアル端末、デモ動作、アナログ入力を扱います。ただし、これらを
無条件に競合させず、後述する手動入力状態とデモ状態によって出力元を一意に決定します。

Web サーバー、シリアル受信、ボタン、ADC、デモ更新、LED 更新は、互いを長時間ブロックしない
形で処理します。どの入力経路から状態が変わっても ESP32 が単一の制御状態を保持し、GPIO 27、
Web UI、シリアル応答、表示 LED が矛盾しないようにします。

## 起動時の状態

正常起動時の初期状態は次のとおりです。

| 項目 | 初期状態 |
| --- | --- |
| 手動入力 | 無効 |
| デモ | 有効 |
| 出力元 | デモ |
| モード表示 LED | デモが有効なため点灯 |
| エラー LED | 起動中は点滅し、正常起動完了後に消灯 |

デモは速度の最小値から開始します。起動途中では GPIO 27 を安全な停止状態に保ち、必須初期化が
完了してからデモ出力を開始します。安全な停止状態は接続先の要件を確認して実装前に確定します。

## 制御状態、優先順位、遷移

ESP32 は少なくとも、設定速度、直接指定周波数、現在の出力周波数、デモ有効、手動入力有効、
ADC 値、Wi-Fi 状態を保持します。

出力の優先順位は次のとおりです。

1. **手動入力が有効:** ADC 値から求めた速度だけを GPIO 27 へ反映する。
2. **手動入力が無効かつデモが有効:** デモが生成した速度を反映する。
3. **手動入力とデモが無効:** 最後に受理した Web UI またはシリアルの設定を反映する。

手動入力中に Web UI の速度・デモスイッチ、シリアルの `speed`・`freq`・`demo` を操作しても、
要求を適用せず「手動入力中」のエラーを返します。値を保留して後から適用することもしません。
状態参照と `help` は利用できます。Web UI は手動入力中であることと ADC 由来の現在速度を表示し、
無効な操作要素を操作不能にします。

ボタンを 1 回押すたびに手動入力の有効・無効を切り替えます。チャタリング除去を行い、長押しを
複数回の押下として扱いません。手動入力へ入るとデモ処理を一時停止し、ADC 由来の速度を直ちに
出力します。手動入力を終了するとデモ有効状態へ戻り、デモ出力を再開します。起動時にデモが
有効であること、および手動入力中はデモ切り替え要求を拒否することから、この遷移は一意です。

## 速度とパルス出力

速度入力は既存の変換式を共通して使用します。

```text
frequency [Hz] = speed * 6.472 + 5.070
```

通常時は、最後に正常に受理した Web UI または `speed` / `freq` コマンドを反映します。
`freq` は Hz 単位で直接出力し、Web UI に表示する速度は逆変換します。丸め規則は実装前に
確定します。GPIO 27 は既存仕様どおり 50% デューティ比とします。

## Web UI

ESP32 上の HTTP サーバーはルートページ `/` に次の要素を提供します。

- 速度の最小値から最大値までを選べるスライダー
- スライダーと同じ速度を数値で編集できるテキストボックス
- デモを有効・無効にするスイッチ
- 手動入力状態、入力元、現在速度、周波数、デモ状態、入力エラーの表示

スライダーとテキストボックスは双方向に連動します。速度またはデモ状態が Web、シリアル、
デモ、アナログ入力、ボタンのいずれで変化しても、再読み込みなしで全クライアントへ反映します。
同期方式と Web サーバーライブラリは実装時に選定できます。

手動入力中は速度入力とデモスイッチを無効表示にし、送信済みの変更要求もサーバー側で拒否します。
クライアント側の無効化だけを排他制御として信用してはいけません。

HTTP のメソッド、パス、要求・応答形式、ステータスコード、エラー、使用例は、実装と同じ変更で
README または `docs/` に確定仕様として追記します。

## シリアル端末

115200 bps のターミナル形式とし、起動時に使い方を表示します。改行でコマンドを確定し、成功時は
適用値、失敗時は理由と使用方法を返します。最低限、次のコマンドを提供します。

```text
help
speed <速度>
freq <周波数Hz>
demo on
demo off
```

空入力、不明なコマンド、引数不足、余分な引数、数値でない入力、負値、ゼロ、オーバーフロー、
範囲外を区別して通知します。手動入力中の制御コマンドは構文と値を検証したうえで拒否し、
GPIO 27、デモ状態、保存済み設定を変更しません。

## アナログ手動入力とボタン操作

可変抵抗を ESP32 の ADC 入力へ接続し、手動入力中だけ継続的に読み取ります。ADC の有効最小値・
最大値を速度の最小値・最大値へ線形変換し、共通の速度―周波数変換を通して GPIO 27 へ出力します。

```text
speed = speed_min
      + (adc - adc_min) * (speed_max - speed_min) / (adc_max - adc_min)
```

ADC 値は有効範囲へ制限し、ノイズで出力が不安定にならないよう平滑化またはヒステリシスを設けます。
ADC の分解能、減衰、サンプリング周期、丸め規則は実装時に明記します。ADC 入力 GPIO、ボタン入力
GPIO、プルアップ／プルダウン、押下論理も基板仕様を確認して決定し、各ピン番号は専用の
設定ファイルへ `constexpr` として定義します。

利用手順は次のとおりです。

1. ボタンを押して手動入力へ切り替える。
2. モード表示 LED が点滅したことを確認する。
3. 可変抵抗を操作してアナログ値を入力する。
4. 線形変換された速度が GPIO 27 へ出力される。
5. ボタンをもう一度押して手動入力を終了する。
6. デモ出力が再開し、モード表示 LED が点滅から点灯へ切り替わる。

## デモ動作

デモは速度の最小値から最大値まで一定周期で増加し、最大値に達したら減少、最小値に達したら
再び増加する往復動作です。`delay()` による長時間待機を避け、時刻差分で更新します。速度の
最小値、最大値、増分、更新間隔は安全な値を実装前に決定します。

Web UI またはシリアルでデモを無効にすると、最後に受理した通常設定へ移ります。手動入力中は
デモ更新を一時停止し、デモの切り替え要求を拒否します。手動入力終了時にはデモを有効に戻し、
最小値から往復動作を再開します。

## Wi-Fi、AP、mDNS

起動時は指定 SSID への STA 接続を設定時間だけ試行します。成功時はそのネットワーク上で
サーバーを公開し、タイムアウト時は ESP32 が同じ SSID の AP を開始します。AP の予定アドレスは
`192.168.4.1/24`、HTTP ポートは `80` とします。

STA または AP の準備後、設定したホスト名で mDNS を開始し、`http://<hostname>.local/` で
アクセス可能にします。mDNS 初期化にもタイムアウトを設けます。起動ログには動作形態、IP、
mDNS URL を表示します。

## 設定ファイルとピン管理

Wi-Fi、mDNS、ハードウェアの設定は専用の設定ファイル 1 つに集約し、コンパイル時に確定できる
値を `constexpr` で定義します。少なくとも次の値を同じファイルで管理します。

| 分類 | 設定値 |
| --- | --- |
| Wi-Fi | SSID、パスワード、STA 接続タイムアウト、AP アドレス |
| mDNS | ホスト名、初期化タイムアウト |
| パルス出力 | GPIO 27 のピン番号 |
| アナログ入力 | ADC 入力のピン番号 |
| デジタル入力 | 手動入力切り替えボタンのピン番号 |
| LED 出力 | エラー LED とモード表示 LED の各ピン番号 |

ピン番号は `pinMode()`、`digitalRead()`、`digitalWrite()`、`analogRead()`、`ledcAttachPin()`
などの呼び出し箇所へ数値リテラルとして直接記述せず、設定ファイルの名前付き `constexpr` だけを
参照します。これにより、基板に合わせたピン割り当てを 1 か所で確認・変更できるようにします。

パルス出力は現在の GPIO 27 を維持します。ADC、ボタン、2 個の LED の具体的なピン番号は、
ESP32 の ADC 制約、起動ストラップ、Wi-Fi 使用時の制約、入出力能力、および各信号の電気仕様を
確認して実装前に決定します。ピンの重複はコンパイル時または初期化時に検出できるようにします。
実運用の Wi-Fi 認証情報はコミットしません。

## 2 個の表示 LED

LED はエラー表示用とモード表示用の 2 個を使用します。どちらも **正極性** で、GPIO に
`HIGH`（1）を出力すると点灯し、`LOW`（0）で消灯します。

| LED | 点灯条件 | 点滅条件 | 消灯条件 |
| --- | --- | --- | --- |
| エラー LED | エラーが発生したとき | 起動中 | 正常に起動を完了し、通常動作しているとき |
| モード表示 LED | デモが有効なとき | 手動入力が有効なとき | 手動入力とデモがともに無効なとき |

手動入力とデモは同時に出力を制御しないため、モード表示 LED の状態は一意に決まります。ボタンで
手動入力を有効にすると連続点灯から点滅へ切り替え、手動入力を終了してデモへ戻ると点滅から
連続点灯へ切り替えます。Web UI またはシリアルでデモを無効にした通常入力状態では消灯します。

エラー LED は ESP32 が GPIO を駆動する前から点灯するよう、ハードウェアによってデフォルト ON
にします。起動処理を開始したら点滅させ、すべての必須初期化が成功して通常動作へ移ったときだけ
消灯します。起動中または通常動作中にエラーが発生した場合は点滅・消灯より連続点灯を優先します。
回復不能なエラーで停止するときは、シリアルへ処理名と理由を表示し、GPIO 27 を安全な停止状態に
します。STA 接続タイムアウトは AP フォールバック条件なので停止エラーではありません。

点滅周期とデューティ比は実装前に定義し、Web、シリアル、ADC、ボタンを妨げない非ブロッキングな
時刻差分方式で駆動します。

2 個の LED の GPIO と電流制限抵抗は、起動ストラップや他の入出力と衝突しない値を実装前に
確定し、各 GPIO は専用の設定ファイルへ `constexpr` として定義します。

## 入力検証と安全性

- Web、シリアル、ADC で同じ速度・周波数範囲を使用する。
- 演算オーバーフローと LEDC が扱える周波数・分解能を API 呼び出し前に検証する。
- 無効または現在の状態で許可されない入力では、出力と保存済み状態を変更しない。
- ボタンのチャタリングと ADC ノイズを考慮する。
- 起動中・停止エラー時の GPIO 27 の状態を定義し、実機で波形を確認する。
- GPIO 27 の周波数、50% デューティ比、停止状態の変更はハードウェア影響として扱う。

## 受け入れ条件

- 起動時に手動入力が無効、デモが有効で、デモが最小速度から開始する。
- Web とシリアルの速度・周波数・デモ操作が通常時に GPIO 27 と全 Web UI へ反映される。
- ボタンを 1 回押すと手動入力が有効になり、モード表示 LED が点灯から点滅へ切り替わり、
  ADC 値が速度へ線形変換される。
- 手動入力中の Web・シリアル・デモ制御が拒否され、ADC だけが出力を変更できる。
- 再度ボタンを押すとデモが最小速度から再開し、モード表示 LED が点灯へ切り替わる。
- STA 接続成功時は STA、タイムアウト時は AP で Web UI を利用できる。
- エラー LED が正極性で、電源投入時 ON、起動中点滅、正常動作中 OFF、エラー時 ON になる。
- モード表示 LED が正極性で、デモ中 ON、手動入力中点滅、両方が無効な通常入力中 OFF になる。
- パルス出力、ADC、ボタン、2 個の LED の全ピン番号が 1 つの設定ファイルに `constexpr` として
  集約され、機能実装にピン番号の数値リテラルが重複しない。
- 範囲境界、不正入力、競合入力、ボタンチャタリング、ADC ノイズ、Wi-Fi フォールバック、
  初期化失敗を検証する。

## 実装前に確定する値

- 速度・周波数の最小値と最大値、速度の単位、逆変換の丸め規則
- ADC の GPIO、有効範囲、分解能、減衰、周期、平滑化方式（GPIO は設定ファイルへ集約）
- ボタンの GPIO、入力論理、プル設定、デバウンス時間（GPIO は設定ファイルへ集約）
- デモの増分と更新間隔
- GPIO 27 の起動中・停止時の安全な出力状態
- 2 個の LED の GPIO、抵抗値、点滅周期とデューティ比（GPIO は設定ファイルへ集約し、
  極性と状態条件は確定済み）
- AP と STA で同じ SSID を使う場合の識別方法
